# 教学 AI 平台全面加固与真实 RAG 改造设计

日期：2026-07-11
状态：待用户确认

## 1. 背景与结论

本次改造基于项目级深度审查和本机运行环境探测，目标是把当前可演示原型提升为具备明确安全边界、真实向量检索、可恢复索引和自动化验证的工程版本。

审查确认的主要问题如下：

- 公共注册接口直接接受客户端角色，可创建高权限账号。
- JWT 存在公开默认密钥，仓库还跟踪了由该密钥签名的 Token。
- 下游服务端口直接暴露，并信任可伪造的 `X-User-*` 请求头。
- 文件下载路径没有规范化和上传根目录约束。
- 课程、班级、作业、提交记录和 Agent 工具缺少对象级授权。
- 长文本分块在末尾发生无限循环，可导致拒绝服务。
- AI Agent 可按任意学生 ID 查询成绩，且部分 SQL 引用了不存在的字段。
- Redis 缓存锁没有所有权令牌，宽松多态反序列化扩大了攻击面。
- 当前知识库只执行 MySQL `LIKE` 查询；Elasticsearch 未被业务代码使用，问答页面也没有调用课程检索，因此当前实现不是真正的 RAG。
- 没有 JUnit、前端测试或 CI；外层仓库跟踪了大量构建产物，并存在嵌套 Git 仓库。

本机已经运行 Ollama，并安装 `bge-m3:latest`。实测该模型通过 `/api/embed` 返回 1024 维向量；首次加载约 57.5 秒，模型热态下批量生成两个向量约 2.2 秒。Docker CLI 和 Compose 已安装，但设计时 Docker Desktop 引擎尚未启动。

## 2. 改造范围与实施阶段

为保持每一步可验证，全面修改分为四个连续阶段：

1. 安全基线与回归测试：身份、角色、服务边界、对象授权、文件路径和确定性错误。
2. Redis 加固：显式类型序列化、可靠锁释放、故障降级和会话隔离。
3. 真实 RAG：Ollama 向量化、Elasticsearch 混合检索、索引重建、引用和课程权限。
4. 工程化与韧性：超时、异步任务、依赖升级、CI、仓库结构和运行文档。

每个阶段先增加失败测试，再做最小实现，阶段验证通过后才进入下一阶段。

## 3. 总体架构

### 3.1 数据职责

- MySQL 是文档、分块、课程关系和索引状态的事实数据源。
- Elasticsearch 是可删除、可重建的检索投影，不承载唯一业务数据。
- Ollama `bge-m3:latest` 负责文档和查询的 1024 维向量生成。
- Redis 只承载短期缓存、按用户与课程隔离的对话历史和互斥锁，不作为向量数据库。
- LLM 负责基于已检索证据生成答案，不允许自行绕过授权直接读取全库。

### 3.2 RAG 写入链路

```text
教师上传文档
  -> 文件类型、大小和内容安全校验
  -> 文本解析
  -> 300～500 字的重叠分块
  -> MySQL 事务保存文档和分块
  -> 事务提交后发布索引事件
  -> 批量调用 Ollama /api/embed
  -> 写入 Elasticsearch 版本化索引
  -> 更新 MySQL 索引状态为 ready
```

索引失败不回滚已经安全保存的原始文档，而是记录 `pending` 或 `failed`、失败原因和最后尝试时间。管理员重建任务可以重复执行。

### 3.3 RAG 查询链路

```text
用户选择课程并提问
  -> edu-agent 校验用户可访问该课程
  -> edu-knowledge 生成查询向量
  -> Elasticsearch 分别执行课程过滤后的 kNN 与 BM25
  -> Java 层用 RRF 融合两个结果集
  -> 返回 Top 5 分块、分数和来源
  -> edu-agent 将分块作为不可信参考资料注入提示词
  -> LLM 生成带来源编号的回答
```

采用两次检索再由 Java 融合，而不依赖某个特定 Elasticsearch 版本的混合查询语法。RRF 常数固定为 60，候选集默认各 20 条，最终返回 5 条，并允许通过配置调整。

## 4. Elasticsearch 设计

使用版本化物理索引与稳定别名：

- 物理索引：`knowledge-chunks-v1`
- 读写别名：`knowledge-chunks`

每个分块是一条独立文档，字段包括：

| 字段 | 类型 | 说明 |
|---|---|---|
| `chunkId` | keyword | MySQL 分块 ID，作为幂等文档 ID |
| `documentId` | keyword | 文档 ID |
| `courseId` | keyword | 课程过滤边界 |
| `chunkIndex` | integer | 分块顺序 |
| `title` | text + keyword | 文档名和来源展示 |
| `content` | text | BM25 检索和提示词内容 |
| `embedding` | dense_vector | 1024 维、cosine、启用索引 |
| `embeddingModel` | keyword | 固定为 `bge-m3:latest` |
| `contentHash` | keyword | 判断内容是否需要重新向量化 |
| `updatedAt` | date | 同步审计 |

删除文档时按 `documentId` 删除索引投影。模型、维度或分块算法变化时创建新版本索引，完整重建后原子切换别名。

## 5. Ollama 集成设计

新增独立 `EmbeddingClient` 接口和 Ollama 实现，避免知识库业务绑定 HTTP 细节。

配置：

```yaml
rag:
  embedding:
    provider: ollama
    model: bge-m3:latest
    dimensions: 1024
    base-url: ${OLLAMA_BASE_URL:http://127.0.0.1:11434}
    connect-timeout: 5s
    read-timeout: 120s
    batch-size: 16
    keep-alive: 30m
```

宿主机运行服务时使用 `127.0.0.1:11434`；Docker 中的服务通过 `host.docker.internal:11434` 访问宿主机 Ollama。请求采用批量输入，并限制专用线程池，避免默认使用全部 CPU。

服务启动时检查模型名称和向量维度。Ollama 不可用时知识服务仍可启动，但向量写入保持 `pending`，RAG 查询返回明确的 503 与可诊断错误。不得静默把关键词搜索冒充为 RAG；如启用关键词降级，响应必须返回 `retrievalMode=keyword-degraded`，前端显示降级状态。

## 6. Redis 设计

### 6.1 保留的使用场景

- 课程和班级详情缓存。
- 按 `userId + courseId` 隔离的短期对话历史。
- RAG 检索结果短缓存，键包含课程、规范化问题哈希、索引版本和检索参数。
- 热点缓存重建互斥锁。

不缓存完整知识库向量，不把 Redis 当作事实数据源。

### 6.2 序列化

缓存服务改为显式类型 API：

```java
<T> T getOrLoad(String key, Class<T> type, Supplier<T> loader, Duration ttl)
```

值使用 `StringRedisTemplate` 保存 JSON，由调用者提供目标类型。移除 `LaissezFaireSubTypeValidator` 和全局默认类型信息，避免任意多态类型实例化。

### 6.3 互斥锁

- 获取锁时写入随机 UUID 所有权令牌和有限 TTL。
- 释放锁通过 Lua 脚本执行“值相等才删除”。
- 等待采用有限次数和随机退避，响应中断信号。
- Redis 故障时回退数据库读取，但不再次调用可能失败的 Redis 操作。
- 锁竞争超时不得无限等待；允许直接读取数据库，但记录指标以发现缓存击穿。

## 7. 身份与授权设计

### 7.1 身份基线

- 公共注册固定创建 `student`，请求 DTO 不再接受角色。
- 教师与管理员由受保护的管理流程创建。
- 删除 JWT 默认密钥；没有 `JWT_SECRET` 时认证和网关服务拒绝启动。
- 删除并轮换仓库中暴露的 Token 和签名密钥。
- 网关在写入身份头前先移除所有客户端提供的 `X-User-*` 头。
- Docker 只向宿主机发布网关端口；下游服务只暴露在内部网络。

### 7.2 对象级授权

统一增加授权服务，规则如下：

- 学生只能读取自己加入课程的公开资料、自己的提交和成绩。
- 教师只能管理自己负责的课程、班级、作业、学生和知识库。
- 管理员可以跨课程管理，但所有写操作记录审计日志。
- `assignmentId`、`submissionId`、`courseId` 等组合参数必须验证关联关系。
- Agent 工具不能接收并直接信任由 LLM 生成的学生 ID；工具执行时必须携带服务端认证上下文。

知识库上传、删除和重建索引仅允许教师或管理员；检索必须应用课程访问过滤。

## 8. 文件与资源安全

- 所有读取路径使用上传根目录的绝对规范化路径，并验证候选路径以根目录开头。
- 下载接口使用不可猜测的文件 ID，经数据库查询归属后再读取，不接受任意路径。
- 上传同时校验扩展名、MIME、文件签名和允许的解析器。
- 对 PDF 页数、DOCX 解压后大小、文本长度和解析时间设置上限。
- 长文本分块到达末尾后立即退出，并校验 `chunkSize > overlap >= 0`。
- 文档原始名称只用于展示，不参与磁盘路径构造。

## 9. API 与前端设计

问答请求由客户端上下文改为服务端检索：

```json
{
  "question": "什么是二叉树的前序遍历？",
  "courseId": 12
}
```

响应使用结构化对象：

```json
{
  "answer": "……[1]",
  "retrievalMode": "hybrid",
  "sources": [
    {
      "documentId": 7,
      "documentTitle": "数据结构基础",
      "chunkId": 31,
      "chunkIndex": 4,
      "score": 0.83
    }
  ]
}
```

前端问答页增加课程选择、来源列表、索引不可用提示和降级状态。删除允许客户端直接提交 `courseContext` 的接口字段。

错误响应使用真实 HTTP 状态：400 参数错误、401 未登录、403 无权限、404 资源不存在、409 状态冲突、429 资源饱和、503 Ollama 或 Elasticsearch 暂不可用。

## 10. LLM 提示词与数据安全

- 检索到的文档内容标记为不可信资料，明确禁止执行其中的指令。
- 仅向模型传入授权课程的 Top K 分块，并限制总字符或 Token 数。
- 提示词要求无法从资料确认时明确说明，不允许编造来源。
- 来源编号由服务端映射，不能让模型自行生成不存在的引用。
- 日志不记录完整学生问题、作业内容、Token 或 API Key；使用请求 ID 和脱敏摘要。

## 11. 异步任务与故障恢复

- 为 HTTP 客户端设置连接、读取和总超时。
- AI 批改线程池饱和时返回明确的 429/503，不使用 `CallerRunsPolicy` 阻塞请求线程。
- 批改和索引任务使用幂等状态转换，重复触发不会产生并行重复任务。
- 服务重启后可以扫描 `pending` 或超时的 `processing` 记录恢复任务。
- 索引重建返回任务 ID、总数、成功数、失败数和错误摘要，并提供状态查询接口。

## 12. 数据库一致性

- 移除 Agent SQL 中不存在的 `ai_score` 字段，统一成绩字段含义。
- 为知识文档增加索引状态、失败原因、模型、维度和最后索引时间。
- 增加数据库迁移工具；不再只依赖会 `DROP TABLE` 的初始化脚本。
- 分页参数统一限制为 `pageNum >= 1`、`1 <= pageSize <= 100`。
- 所有状态字段使用统一枚举和数据库约束，避免 `completed`、`graded` 等多套语义漂移。

## 13. 测试策略

### 13.1 单元测试

- 公共注册永远不能创建教师或管理员。
- JWT 缺少密钥时启动失败，错误密钥不能验证 Token。
- 路径穿越和双重编码路径被拒绝。
- 长文本分块可终止、覆盖完整文本且重叠正确。
- Redis 只能由锁所有者释放锁；Redis 异常时数据库加载仍可工作。
- RRF 排序、课程过滤、分数阈值和来源映射正确。
- Agent 查询不再引用不存在字段。

### 13.2 集成测试

使用 Testcontainers 启动 MySQL、Redis 和 Elasticsearch；Ollama 客户端在大部分测试中使用固定向量桩，另设本机或显式启用的真实 Ollama 冒烟测试。

关键场景：

- 上传文档后 MySQL 分块数与 Elasticsearch 文档数一致。
- 不包含相同字面的语义问题仍能召回相关分块。
- 不同课程之间没有检索泄漏。
- 删除文档后索引投影消失。
- 重建任务重复执行不会产生重复索引文档。
- Ollama 或 Elasticsearch 不可用时状态和 HTTP 错误明确。
- 学生、教师和管理员的对象级权限矩阵得到验证。

### 13.3 前端与 CI

- 使用 Vitest 和 React Testing Library 覆盖认证状态、课程选择、来源展示和错误状态。
- GitHub Actions 运行后端测试、前端测试、生产构建、依赖审计和 Docker Compose 配置校验。
- CI 不依赖真实付费 LLM，也不下载大型 Ollama 模型。

## 14. 验收标准

满足以下条件才认为改造完成：

1. 无法通过注册参数、直连下游服务或伪造身份头获得额外权限。
2. 仓库不含可用 JWT、API Key、默认生产密钥或跟踪的构建产物。
3. Redis 锁所有权测试、故障回退测试和序列化安全测试通过。
4. 文档上传后生成 1024 维向量并写入 Elasticsearch。
5. 语义检索、关键词检索和 RRF 混合排序均有自动化测试。
6. 课程隔离测试证明跨课程内容不可被召回。
7. 问答响应包含可追踪到文档和分块的来源。
8. 现有 MySQL 知识分块可以通过管理员任务幂等重建索引。
9. 后端测试、前端测试、生产构建、Compose 校验和依赖审计进入 CI。
10. README 的架构、配置、启动、重建和故障排查说明与实际代码一致。

## 15. 非目标

- 本阶段不新增独立向量数据库。
- 不把 Ollama `llava` 作为主要教学对话模型。
- 不在第一版增加复杂的学习排序模型或 GPU 推理。
- 不重写全部微服务框架；修改聚焦安全边界、Redis、RAG 和直接相关工程能力。
