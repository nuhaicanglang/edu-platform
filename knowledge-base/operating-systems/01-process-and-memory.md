# 操作系统：进程管理与内存管理

## 一、进程管理

### 1. 进程 vs 线程

| 对比项 | 进程 | 线程 |
|-------|------|------|
| 资源 | 独立地址空间、文件描述符 | 共享进程资源 |
| 切换开销 | 大（需切换页表等） | 小 |
| 通信 | IPC（管道/信号/共享内存） | 直接读写共享内存 |
| 崩溃影响 | 不影响其他进程 | 导致整个进程崩溃 |
| 创建开销 | 大（fork系统调用） | 小（pthread_create） |

### 2. 进程状态转换

```
                 ┌──────────────────────────────────┐
                 │                                  │
  创建 ──► 就绪  ◄──── 运行 ──── 时间片用完 ──► 就绪
             │         │
           调度器    I/O请求/等待事件
             │         │
             └──►  运行  ◄────── 阻塞  ◄──── I/O请求
                   │                  I/O完成/事件发生
                   └──► 终止
```

### 3. 进程调度算法

**FCFS（先来先服务）**
```
进程  到达  执行时间
P1    0     10
P2    1     5
P3    2     3

调度顺序：P1(0-10) → P2(10-15) → P3(15-18)
平均等待时间：(0 + 9 + 13) / 3 = 7.33
```

**SJF（最短作业优先）**
```
调度顺序：P1(0-10) → P3(10-13) → P2(13-18)
平均等待时间：(0 + 12 + 8) / 3 = 6.67   ← 最优（非抢占）
```

**RR（时间片轮转，quantum=4）**
```
调度顺序：P1(0-4) → P2(4-8) → P3(8-11) → P1(11-15) → P2(15-16) → P1(16-17)
平均等待时间：(6 + 7 + 6) / 3 = 6.33
响应时间好，但上下文切换开销大
```

**优先级调度** — 高优先级先执行，注意饥饿问题（老化算法解决）

### 4. 死锁

**四个必要条件**（Coffman条件）：
1. **互斥**：资源不能同时被多个进程使用
2. **占有并等待**：进程持有资源同时等待其他资源
3. **不可抢占**：已分配资源不能强制收回
4. **循环等待**：存在等待环路 P1→P2→P3→P1

**预防死锁**：破坏某个必要条件
- 资源一次性申请（破坏"占有并等待"）
- 资源排序申请（破坏"循环等待"）

**银行家算法**（死锁避免）：
```
检查安全序列：分配资源后系统是否仍处于安全状态
安全状态 = 存在一个安全序列（所有进程都能完成）
```

## 二、内存管理

### 1. 分页（Paging）

将虚拟地址空间和物理内存都划分为固定大小的页（通常4KB）。

```
虚拟地址 = 虚拟页号(VPN) + 页内偏移(offset)

地址转换过程：
1. CPU生成虚拟地址
2. 提取VPN，查页表 → 物理帧号(PFN)
3. 物理地址 = PFN × 页大小 + offset

TLB（转址旁路缓存）：缓存最近使用的页表项，加速地址转换
TLB命中 → 直接得到物理地址（1次内存访问）
TLB未命中 → 查多级页表（多次内存访问）
```

### 2. 多级页表（64位系统）

```
Linux x86-64四级页表：
虚拟地址(48位) = PGD(9位) | PUD(9位) | PMD(9位) | PTE(9位) | offset(12位)

CR3寄存器 → PGD基地址
→ PUD基地址 → PMD基地址 → PTE基地址 → 物理页帧
```

### 3. 页面置换算法

**最优置换（OPT）**：替换未来最久不使用的页（理论最优，实际不可实现）

**LRU（最近最少使用）**：替换最长时间未使用的页
```
访问序列：7 0 1 2 0 3 0 4 2 3 0 3（内存帧数=3）

帧状态：
7 → [7]         缺页
0 → [7,0]       缺页
1 → [7,0,1]     缺页
2 → [2,0,1]     缺页，替换7（最久未用）
0 → [2,0,1]     命中
3 → [2,0,3]     缺页，替换1
0 → [2,0,3]     命中
4 → [4,0,3]     缺页，替换2
缺页率 = 6/8 = 75%（前8次）
```

**Clock算法（近似LRU）**：
- 给每个页帧加引用位(R)
- 时针扫描：R=1则清零跳过，R=0则替换

### 4. Thrashing（颠簸）

**原因**：进程过多，每个进程分配的物理帧不足，大量时间花在页面置换上

**解决方法**：
- 工作集模型：只保留近期活跃页
- 减少并发进程数
- 增加物理内存

### 5. Linux内存结构

```
进程虚拟地址空间（从低到高）：
┌────────────────┐ 0x0000...
│   代码段(text)  │ 程序代码，只读
├────────────────┤
│   数据段(data)  │ 已初始化全局/静态变量
├────────────────┤
│    BSS段        │ 未初始化全局变量
├────────────────┤
│    堆(heap)     │ malloc/new，向高地址增长
│       ↓        │
│   (空闲区域)   │
│       ↑        │
│    栈(stack)    │ 局部变量、函数调用，向低地址增长
├────────────────┤
│  内核空间(3GB+) │ 用户程序不可直接访问
└────────────────┘ 0xFFFF...
```

## 知识点总结
- 进程是资源分配单位，线程是CPU调度单位
- 死锁需同时满足四个条件，破坏任一可预防
- 分页管理通过页表将虚拟地址转换为物理地址
- TLB是地址转换的硬件缓存，命中率直接影响性能
- LRU是最常用的页面置换算法，Clock是其高效近似实现
